## 1. Problem Statement (문제 정의)
기존의 모닝 루틴(손으로 일기 쓰기, 거울 보며 긍정 확언 외치기 등)은 아침에 의욕이 바닥나 있는 상태의 사용자에게 너무 큰 인지적·물리적 마찰(Cognitive & Physical Friction)을 요구합니다. 그 결과 작심삼일로 끝나거나, 침대에서 일어나지 못한 채 무기력하게 스마트폰 쇼츠/릴스를 소비하며 하루를 불안하게 시작하게 됩니다.

---

## 2. Demand Evidence (수요 및 기회 요인)
- **Zero-Friction 니즈:** 침대에서 눈을 뜨자마자 손가락 타이핑이나 펜을 잡을 필요 없이, 말 한마디로 마음을 정돈하고 싶어 하는 강한 심리적 수요.
- **파편화된 기존 도구의 피로감:** 유튜브에서 음악을 고르느라 알고리즘에 빠져 시간을 허비하고, 좋은 글은 인스타에서 보고, 다짐은 카톡/메모장에 적어 과거 기록을 다시는 찾아보지 못하는 파편화 문제.

---

## 3. Status Quo (현재의 대안과 한계)
- **기존 방식:**
  - 노트에 손일기 쓰기: 바쁜 아침 시간에 꺼내기 부담스럽고 지속하기 어려움.
  - 거울 보고 혼자 소리내어 말하기: 다소 어색하고 시각적/오디오 피드백이 없어 민망함.
  - 유튜브 명상 음악 검색: 검색 과정에서 다른 자극적인 영상(쇼츠 등)으로 이탈.
- **대가(Cost):** 아침의 소중한 20~30분이 도파민 중독이나 무기력함으로 낭비됨.

---

## 4. Target User & Onboarding Personas (타겟 사용자 3대 페르소나)
앱 온보딩 시 사용자가 자신의 상태를 선택하여 맞춤형 큐레이션을 제공받습니다:
1. **번아웃 직장인:** 아침 출근 전 무기력함을 깨고, 짧고 명확한 에너지 회복이 필요한 사람.
2. **취준생 / 이직 준비자:** 아침에 눈뜨자마자 밀려오는 불안감과 자존감 저하를 다스릴 마인드셋이 절실한 사람.
3. **갓생/미라클모닝 작심삼일러:** 손일기의 피로 때문에 루틴 형성에 번번이 실패했던 사람.

---

## 5. Core Premises (핵심 전제)
1. **Voice-First (음성 우선):** 버튼 하나 탭하고 말하면(Web Speech API) 나의 웅얼거림도 텍스트로 깔끔하게 변환 및 정리된다.
2. **Zero-Cognitive Load Music (무선택 음악 스트리밍):** 유튜브를 검색할 필요 없이, 테마별(비 오는 날, 활기찬 아침, 깊은 명상 등) 또는 말 한마디("차분한 재즈 틀어줘")로 즉시 백그라운드 재생된다.
3. **Daily Inspiration (오늘의 활력 글귀):** 선택한 페르소나에 맞춰 마음을 단단하게 해주는 엄선된 한 줄/단락 글귀 제공.
4. **Timeline & Calendar Archiving (날짜별 검색/저장):** 모든 음성 다짐, 들었던 음악, 글귀가 날짜별로 로컬(IndexedDB)에 영구 보관되며 날짜/키워드 검색이 가능하다.

## 6. Approaches Considered (아키텍처 대안 비교)

### Approach A (Recommended): Mobile-First PWA (Next.js / Vite + React + IndexedDB)
- **장점:** 
  - 별도 앱스토어 설치 없이 URL 접속 즉시 사용 가능 ("홈 화면에 추가" 시 네이티브 앱처럼 동작)
  - 브라우저 표준 Web Speech API 내장으로 추가 API 비용 0원
  - YouTube IFrame API로 합법적이고 깔끔한 음악 스트리밍
  - IndexedDB 기반 로컬 저장으로 서버 비용 없이 완전한 개인정보 보호 및 오프라인 작동
- **단점:** iOS 사파리 환경에서 백그라운드 오디오 재생 시 일부 세션 제약 고려 필요.

### Approach B: Flutter / React Native 네이티브 앱
- **장점:** OS 네이티브 백그라운드 오디오 재생 및 기상 알람/푸시 연동 강력.
- **단점:** 빌드/배포 환경 설정 및 스토어 심사 등 초기 출시 속도가 느림.

### Approach C: 메신저 챗봇 MVP (카카오톡/텔레그램)
- **장점:** 사용자 진입장벽이 가장 낮음.
- **단점:** 유튜브 재생 인터페이스 및 날짜별 캘린더 검색 UI 구현에 구조적 한계.

## 7. Recommended Architecture & Tech Stack
- **Frontend:** React 19 / Vite 또는 Next.js (Fast, Lightweight)
- **Styling:** Tailwind CSS + Lucide Icons (모던하고 따뜻한 미니멀 명상 테마)
- **Audio Engine:** YouTube IFrame Player API (무료, 무제한 음악 스트리밍)
- **Voice STT:** HTML5 Web Speech Recognition API (모바일/크롬 네이티브 지원)
- **Storage:** LocalStorage + IndexedDB (초기 서버리스, 향후 원클릭 클라우드 백업 확장 가능)

## 8. Success Criteria (성공 지표)
1. 앱 진입 후 **3초 이내에 음악이 재생**되고 오늘의 글귀가 표시되는가?
2. 폰을 쥐고 **음성으로 30초 말했을 때 정확하게 오늘의 다짐으로 기록**되는가?
3. 캘린더 뷰에서 **지난 날짜의 다짐과 음악을 즉시 검색 및 조회**할 수 있는가?
